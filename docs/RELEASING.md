# Building and releasing Agenda+

## Reproducible environment

Use Node 22 (`.nvmrc`), npm 10, and `npm ci` at the repository root.
The committed `.npmrc` retains the dependency graph's legacy peer resolution;
use the same setting when updating the lockfile. Install Electron dependencies
separately with `npm --prefix electron ci`. Never fix a build by deleting the lockfile.

`npm run build` exports the frontend into `out/`. It builds an isolated source copy
without API routes or the unrelated Kotlin sources under `src/main/`; the original
source tree is never renamed. Fonts are installed npm assets and work offline.
`npm run build:server` creates the separate Next.js standalone backend in
`electron/backend/`. Backend services are not embedded in the Android APK.

## Android

Use JDK 21, Android SDK platform 36, build tools 36.0.0, AGP 8.13.0,
and the committed Gradle 8.14.3 wrapper. These follow the Capacitor 8 migration
baseline: https://capacitorjs.com/docs/updating/8-0 .

- `npm run android:debug`: export, sync, and build the debug APK.
- `npm run android:apk`: export, sync, and build the signed release APK.
- `npm run android:aab`: export, sync, and build the signed release AAB.
- `cd android` then `./gradlew testDebugUnitTest lintDebug`: run Android checks
  (`gradlew.bat` on Windows).

The existing Android application ID `com.example.agendaplus` is deliberately
preserved. Confirm the final store identifier before the first public release;
changing it afterward creates a different installed app and can strand local data.
Root `capacitor.config.ts` is the source of truth. Electron's copy is generated by sync.

### Signing

Create your upload keystore securely and copy `android/keystore.properties.example`
to `android/keystore.properties`. Fill all four properties. `storeFile` resolves
relative to `android/app/`. Keep passwords, properties, and keystores out of git.
Back up the keystore and credentials. Release tasks reject absent signing settings;
they never fall back to debug signing.

The Android workflow always builds and uploads a debug APK. For signed builds,
configure these secrets in the `production` GitHub environment, then manually run
**Android CI** with `release=true`:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_STORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

That job builds APK/AAB, runs release lint, verifies the APK signature, and uploads
artifacts. It does not submit to Google Play. Increment versionCode and versionName
in `android/app/build.gradle` before subsequent store uploads.

## Electron / Windows

Run `npm ci`, `npm --prefix electron ci`, then `npm run electron:build` on Windows.
The NSIS installer is written to `electron/dist/`. `npm run electron:pack` creates
an unpacked application. The build packages static assets and the standalone backend;
installed users do not need Node, npm, Git, or a source checkout.

The backend runs using Electron's Node runtime on a dynamically selected loopback
port. API requests carry a per-launch token through the limited preload bridge.
Process shutdown affects only processes started by Agenda+. Ollama and a compatible
model remain optional external dependencies for AI; portal automation additionally
needs a compatible installed Chrome/Edge browser. Core local planning must work
when these optional dependencies are absent.

`npm run test:backend` copies the backend outside the checkout, starts it, and tests
health and API access control. `npm --prefix electron run test:smoke` launches the
packaged Windows application with a temporary profile and checks frontend loading,
preload IPC, and backend readiness. CI runs both after building the installer.
The automated smoke test launches the unpacked packaged executable; manually test
the NSIS install/uninstall flow on a clean Windows machine before publishing.

The ordinary Electron Windows Build workflow produces unsigned verification artifacts.
The Verified public preview workflow builds Windows separately in the production
environment and requires signing. Configure these production environment secrets:

- `WIN_CSC_LINK`: the base64-encoded production Windows code-signing certificate.
- `WIN_CSC_KEY_PASSWORD`: the certificate password.

`npm run electron:build:signed` runs the normal frontend/backend packaging pipeline
with electron-builder's `forceCodeSigning=true`. Missing credentials must fail;
unsigned output is never a successful public-preview build. Before uploading,
the workflow requires valid Authenticode signatures on every NSIS installer and
`electron/dist/win-unpacked/Agenda+.exe`, and runs backend and packaged-app checks.
Unsigned PR verification remains available through Electron Windows Build.

On Windows with signing credentials configured in the environment, validate with:

```powershell
npm ci
npm --prefix electron ci
npm run electron:build:signed
npm run test:backend
npm --prefix electron run test:smoke
Get-ChildItem electron/dist/*.exe | Get-AuthenticodeSignature
Get-AuthenticodeSignature -LiteralPath 'electron/dist/win-unpacked/Agenda+.exe'
```

Both signature checks must report Valid. In a separate shell without signing
credentials or an available signing identity, the signed build must fail.
No certificate or store submission credentials are created by this change.
macOS/Linux packaging remains unverified.

## Release acceptance

Before publishing, require passing frontend, Android, and Windows jobs on the same
commit. Verify task creation/completion and persistence after restart, navigation,
file import, offline operation, and clear failures when optional AI/portal services
are absent. Test the APK on a real Android device and the installed desktop app on
a clean Windows account. Review dependency advisories and licensing, configure
production signing, back up local data, and test upgrades from the previous version.

The repository's existing dependency upgrade branch is separate work. Do not merge
it blindly: reconcile it with main, use Node 22, and rerun all platform checks.

## Coursework and tutor verification

Run `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`, and
`npm run test:prod`. The production tests import all coursework kinds, check
unknown dates, deliberately fail a diagnostic, and check remediation and saved
progress. The scraper fixture checks shadow roots and iframes. For an installed
Chromium, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to its executable path.

AI explanations use the official Ollama chat endpoint with JSON-schema validation.
Set `OLLAMA_BASE_URL` and `OLLAMA_MODEL` on the optional backend; defaults are
http://127.0.0.1:11434 and budd-ie:latest. No model is downloaded automatically.
Android’s static app supports local text import and supported diagnostic practice
without a PC. Broader AI explanations and automatic portal scraping need the
optional reachable backend. Do not describe a static APK as containing server API
routes. Desktop includes the standalone backend.

After platform verification and production signing configuration, manually run
`Verified public preview` with `v0.1.1-preview.1`. Its source, Windows and Android
jobs must all pass before signed APK/AAB, Windows installer and checksums can be
published. Existing v0.1.0 source downloads are preserved.
